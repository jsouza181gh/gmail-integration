# Painel web (subprojeto 4b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Painel web responsivo (Vite + React + TypeScript) do Inbox Agent, fiel ao design fechado, servido pela própria API FastAPI em `/` na mesma origem.

**Architecture:** SPA em `web/` que fala só com `/api/*` (cookies HttpOnly + header CSRF). Toda resposta da API passa por schema zod na borda (equivalente do Pydantic do backend) e os tipos TS saem de `z.infer`. CSS do design system copiado como está (tokens + bundle + app.css), sem Tailwind. O build vai para a imagem Docker (estágio Node) e a API serve `web/dist` com fallback de SPA; o nginx do host só precisa de `location /` apontando para `127.0.0.1:8000`.

**Tech Stack:** Vite, React 19, TypeScript strict, react-router, @tanstack/react-query, zod, lucide-react, @fontsource/outfit + @fontsource/jetbrains-mono (fontes locais: a CSP da API é `default-src 'self'`), Vitest + Testing Library + MSW, ESLint (`no-explicit-any`). Versões: as estáveis atuais na hora do `npm install` (travadas no `package-lock.json`).

**Spec:** `docs/superpowers/specs/2026-11-19-gmail-assistant-design.md` (seção do front, abas); design fechado em https://claude.ai/artifact/Xdw4XaUk6MN93neB7JWUrM (canvas "Inbox Agent — Painel", telas `Main`, `Caixa`, `Aprovacoes`, `Documentos`, `Chat`, `Execucoes`, `Agente`, `Seguranca`, `Login`, `M-*`) e design system https://claude.ai/artifact/Fqx4QDo6vHvxTBQoSsAdEw. ## Global Constraints

- **Uma cor só** (brasa `--ember-500` #ff6b35 e tons) sobre `--bg` #121212; nada de verde/azul/amarelo/vermelho. Estado = ícone + palavra, nunca outra matiz.
- Cards planos `--card` #232323, raio 24, sem borda nem sombra; tudo que clica é pílula (`radius-full`); fonte Outfit 300–600, JetBrains Mono só em código literal; números com `ia-num` (tabular).
- Sem sobretítulo em MAIÚSCULAS, sem metadados com “·”, sem emoji. Português do Brasil, frases curtas; verbos nos botões (Aprovar, Recusar, Baixar, Reclassificar); formatos `R$ 1.234,56`, `28/11/2026`.
- Ícones Lucide (`lucide-react`), traço 1.75; 22px barra inferior, 18px lateral, 16px em linhas/botões. Abas: Relevantes `Sparkles`, Caixa `Inbox`, Aprovações `CheckCheck`, Documentos `FileText`, Chat `MessageSquare`, Agente `Bot`, Execuções `Activity`, Segurança `ShieldCheck`, Mais `Menu`.
- Responsivo: ≥1024 barra lateral 232px; 640–1023 só ícones (72px); <640 barra inferior fixa de 5 itens (Relevantes, Caixa, Aprovar, Docs, Mais) em vez da lateral.
- Foco: anel `--focus` 2px + 2px. Hover um degrau acima. Desabilitado: opacidade .4. Movimento: 150ms ease-out (200ms em folhas).
- TypeScript `strict`, **`any` proibido** (ESLint `@typescript-eslint/no-explicit-any` como erro; sem `as` para contornar schema). Nada de `dangerouslySetInnerHTML`: assunto, corpo e remetente de e-mail são sempre texto.
- Toda escrita (POST/PUT/DELETE) manda `X-CSRF-Token` = cookie `csrf`; o navegador manda `Origin` sozinho. `refresh` é POST: precisa do CSRF também.
- Regras do João valem na UI: aprovar nunca é automático; bloquear remetente nunca vira `auto`; “excluir” é sempre lixeira.
- Commits em inglês, estilo `feat(web): …`, terminando com a linha `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Branch `feat/web-panel` a partir de `main` (protegida; push com helper do `gh`).
- Execução inline, sem subagentes (preferência do João).

## Desvios deliberados do design (a API não suporta ou o escopo é de outro subprojeto)

- **Chat** (sub 5): rota existe com layout do design, mas só estado vazio + campo desabilitado. Botões de áudio e anexo também ficam de fora.
- **⌘K / barra de comandos**: vira campo de busca real (Caixa e Documentos). Sem paleta de comandos.
- **Contagem por categoria** na Caixa e botão **Flags**: a API não expõe; chips de categoria sem número e um chip “Só relevantes” (`relevant=true`).
- **Estrela / Arquivar** no detalhe do e-mail: não há endpoint (ações só existem como sugestão do agente); omitidos. O detalhe mostra as sugestões pendentes com Aprovar/Recusar.
- **Login** pede “Usuário” (a API usa `username`), não e-mail.
- **Desfazer** em aprovar/recusar: a API não tem desfazer, então a decisão é enviada com atraso de 5 s e o toast cancela antes disso; sair da tela envia na hora.
- Documentos: sem “Copiar código” quando `barcode` é null.

## Review Focus

Entradas que o design não mostra e que mais provavelmente quebram (cada linha tem teste na tarefa dona):

1. **Access JWT de 10 min expira no meio do uso**: 401 → um único `POST /api/auth/refresh` mesmo com várias requisições paralelas (refresh reutilizado derruba a família de sessões) → repete as requisições; se o refresh falhar, volta ao login. (Task 2)
2. **Campos nulos** (`snippet`, `subject`, `received_at`, `is_relevant`, `amount_cents`, `due_on`, `percent`, `eta_hours`): renderizam “(sem assunto)”, “—” etc., sem `NaN`/“Invalid Date”/crash. (Tasks 3, 6, 9, 10)
3. **E-mail com HTML/script no assunto ou corpo** (`<img src=x onerror=…>`): aparece como texto literal, nada executa. (Task 7)
4. **Listas vazias e backfill sem total** (`mailbox_total: null`, `percent: null`, `eta_hours: null`, 0 sugestões, caixa vazia, nenhum documento): frase em `ink-muted` + ação, nunca tela em branco. (Tasks 6–10)
5. **Aprovar com `decided` menor que o enviado** (outro lugar já decidiu) ou **429/403**: toast mostra o número real e erro em português; lista é recarregada, seleção descartada. (Task 8)
