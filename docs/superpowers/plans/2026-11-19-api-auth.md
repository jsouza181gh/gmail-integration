# Subprojeto 4a — API autenticada (backend do painel) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything the panel needs from the server — strong single-user auth, the hardened HTTP surface and typed JSON endpoints for every tab (including backfill progress) — so subproject 4b can design and build the front against a finished API.

**Architecture:** The existing `api` container (FastAPI, 1 worker) gains routers under `/api`. Auth state (user, recovery codes, refresh-token families, IP blocks, failures) lives in Postgres; JWT access + opaque rotating refresh in `HttpOnly; Secure; SameSite=Strict` cookies, CSRF double-submit + `Origin` check on writes. The API only reads, records decisions and enqueues jobs; it never calls the LLM and only *reads* Gmail (attachment download, profile count).

**Tech Stack:** FastAPI, SQLAlchemy 2.1, Alembic, argon2-cffi, pyotp, PyJWT, cryptography (Fernet, already installed), qrcode (terminal QR in the CLI), httpx TestClient.

**Spec:** `docs/superpowers/specs/2026-11-19-gmail-assistant-design.md` (sections Segurança, Painel, Personalização; subproject 4).

## Global Constraints

- Pydantic everywhere; `Any` forbidden (mypy strict + `disallow_any_explicit`); **no JSON/JSONB columns**; every new module listed in `mypy.ini`.
- Login: senha → TOTP; usuário único criado via CLI na VPS (`src.cli.create_user`): argon2 + segredo TOTP exibido como QR + 10 recovery codes de uso único.
- Access JWT ~10 min em cookie `HttpOnly; Secure; SameSite=Strict`; refresh opaco ~14 dias guardado como hash, rotação a cada uso; reuso de refresh antigo → revoga a família inteira + evento de segurança + alerta; revogação no logout; listar e revogar sessões.
- Bloqueio por IP: 3 falhas (senha ou TOTP) → IP bloqueado até desbloqueio manual via CLI. IP real de `X-Forwarded-For` só se a conexão vier do proxy local.
- Bloqueio global só em ataque: falhas de ≥3 IPs distintos em 24h → login fechado até desbloqueio na VPS. CLI `src.cli.unlock --ip X` / `--global`.
- Auth obrigatória em toda rota exceto login, webhook e `/healthz`; CORS fechado (mesma origem); CSRF double-submit + checagem de `Origin` em rotas que mudam estado; HSTS, CSP, X-Frame-Options, nosniff; rate limit ~60 req/min por rota; `/docs` e `/openapi.json` desligados em produção.
- Webhook: verificar o JWT OIDC do Pub/Sub no lugar de `?token=` (token continua aceito enquanto o OIDC não estiver configurado).
- Download de anexo: autenticado, URL de curta duração, registrado em `security_events`.
- `security_events`: login ok/falha, bloqueios, reuso de refresh, CSRF inválido, download de anexo.
- Nada que esconda e-mail ou mude estado de leitura roda sem aprovação: a API só aprova/recusa sugestões (execução continua no worker via `execute_action`).
- No pipeline do webhook o agente nunca altera config; mudanças de config via painel ficam registradas em `config_audit` (canal `ui`).
- Public repo: no secrets, host or personal address in code, docs or logs.

## Rulings taken while planning (user asked to skip questions)

- Single FastAPI app, routers per area under `/api`; JSON only; the front (4b) is served by nginx at `/` and proxies `/api` and `/webhooks` → same origin, so no CORS middleware at all.
- Two-step login: `POST /api/auth/login` (password) sets a 5-minute signed `mfa` cookie; `POST /api/auth/2fa` (TOTP or recovery code) issues the session. A password failure and a TOTP failure both count toward the 3-strike IP block.
- TOTP secret stored encrypted (Fernet key from `APP_SECRET`); refresh tokens and recovery codes stored as SHA-256 hashes (high-entropy random values; argon2 only for the password).
- Trusted proxies: `TRUSTED_PROXIES` CIDRs (default `127.0.0.1/32,172.16.0.0/12` — host nginx reaches the container through the docker bridge); then the **last** `X-Forwarded-For` entry (the one nginx appended).
- Rate limit in memory (one uvicorn worker by design): 60 req/min per (IP, route); login/2fa 10/min.
- Semantic search over the vector index needs a query embedding = an LLM call → stays out of the API; it arrives with the chat (subproject 5). The email list has keyword search (`ILIKE` on subject/sender/snippet).
- Taxonomy (categories) is read-only through the API in 4a; editing a taxonomy version is deferred (it re-triggers classification semantics). Agent config versions, policies, rules, KB and `llm_mode` are editable.
- `llm_mode` (`free|fast`) moves to an `app_settings` row read by the worker's gateway on every call (runtime change, spec "alteráveis em runtime"); env stays as the default.
- Backfill progress: `BackfillProgress` + mailbox total (`users.getProfile.messagesTotal`, cached 10 min) + throughput (pages finished in the last hour/24h) + ETA.
- New alert kinds: `ip_blocked`, `global_lock`, `refresh_reuse`, `login_new_ip`.

## Review Focus

1. Refresh token used twice (stolen copy replayed after the real client rotated) → whole family revoked, both clients logged out, `refresh_reuse` event + alert. Pinned in Task 2.
2. Attacker spoofs `X-Forwarded-For` from outside the proxy → header ignored, the peer IP is the one blocked. Pinned in Task 3.
3. Third failure from one IP while the correct password arrives on the 4th try → still blocked (block checked before the password). Pinned in Task 2.
4. State-changing request with a valid session but missing/wrong CSRF header or foreign `Origin` → 403 + `csrf_invalid` event, nothing changes. Pinned in Task 3.
5. Download link replayed after expiry or used for another attachment id → 403. Pinned in Task 6.

**Interfaces:**

- `SecurityLog(sf, alerts)`: `record(kind: SecurityKind, ip: str | None, detail: str) -> None`; `SecurityKind = Literal["login_ok","login_fail","totp_fail","ip_blocked","global_lock","refresh_reuse","logout","session_revoked","csrf_invalid","download","unlock"]`.
- `AuthService(sf, settings, log, clock)`:
  - `check_open(ip) -> Literal["ok","ip_blocked","global_lock"]`.
  - `password_step(username, password, ip) -> LoginStep` (`LoginStep(ok: bool, user_id: int | None, blocked: bool)`); checks `check_open` **before** verifying; failure → `LoginFailure` + `login_fail` event; 3rd failure in 24 h for that IP → `IpBlock` + `ip_blocked` event/alert; failures from ≥3 distinct IPs in 24 h → `global_lock` setting + event/alert.
  - `second_step(user_id, code, ip, user_agent) -> IssuedSession | None`: TOTP (`valid_window=1`) or unused recovery code (marked used); failure counts like a password failure; success → new family, `IssuedSession(access, refresh, csrf, family_id)`, `login_ok` event; first success from a never-seen IP → `login_new_ip` alert.
  - `refresh(raw, ip, user_agent) -> IssuedSession | None`: valid+current → rotate (old `rotated_at`, new row same family); token already rotated → revoke family (`revoke_reason="reuse"`), `refresh_reuse` event + alert, return None; expired/revoked → None.
  - `logout(raw) -> None`; `sessions(user_id) -> list[SessionRow]` (one per live family, newest token's ip/ua/last_used); `revoke_family(user_id, family_id) -> bool`.
  - `unlock_ip(ip) -> bool`, `unlock_global() -> bool` (both log `unlock`).

- Rate limit: 60/min per (ip, route template), 10/min on auth routes → 429 with `Retry-After`.
- Routes: `POST /api/auth/login {username,password}` → 204 + `mfa` cookie | 401 | 423 (blocked); `POST /api/auth/2fa {code}` → 204 + cookies | 401 | 423; `POST /api/auth/refresh` → 204 | 401; `POST /api/auth/logout` → 204; `GET /api/auth/me` → `{username}`; `GET /api/auth/sessions` → `list[SessionOut]` (marks current); `DELETE /api/auth/sessions/{family_id}` → 204.
- `require_user` dependency on every `/api/*` route but login/2fa/refresh; 401 when the access cookie is missing/expired (front calls refresh then retries).
- `/docs`, `/redoc`, `/openapi.json` disabled when `production`.
